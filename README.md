# Spoken BNC Concordancer

Explore words, phrases and collocations in the Spoken British National Corpus 2014 through an interactive concordance interface. This is an independent project and is not an official BNC service.

Built with React, TypeScript, Express, SQLite and Python, this project connects my background in applied linguistics with software development. It turns annotated corpus XML into a searchable database and lets users move from a broad search to individual examples of language in context.

## Features

- **Word searches:** exact matches and prefix, suffix or substring wildcards, such as `hard*`, `*ing` and `*core*`.
- **Lemma searches:** explore the word forms associated with a lemma.
- **Phrase searches:** find consecutive words in their original order. Phrase searches require at least two words and do not accept wildcards.
- **Keyword in context (KWIC):** view each match between its left and right context, with adjustable context size and pagination.
- **Vocabulary variants:** narrow results by word form and available part-of-speech information.
- **Collocation analysis:** explore neighbouring words around a target word or phrase using configurable left/right windows.
- **Distribution charts:** inspect a collocate's relative positions and open concordances for the collocate or a specific position.
- **Result details:** view the utterance and available transcript, speaker and annotation metadata.

## Technology and architecture

| Layer     | Technology and responsibility                                            |
| --------- | ------------------------------------------------------------------------ |
| Frontend  | React, TypeScript, Vite and Tailwind CSS                                 |
| Charts    | Recharts for collocate position distributions                            |
| API       | Express and TypeScript, with separate search and collocation services    |
| Database  | SQLite through `better-sqlite3`                                          |
| Ingestion | Python standard-library XML parsing and SQLite                           |
| Testing   | Jest, Supertest and React Testing Library; Python unittest for ingestion |

The Python ingestion script creates text, utterance and token tables, indexes them, and builds an utterance FTS index. Token records preserve their position and available lemma, part-of-speech, word-class and semantic annotations. Search services use the stored records to construct concordance contexts and collocation results.

The Express application is created separately from its listening server, allowing API tests to inject an in-memory database. On the frontend, `useCorpusSearch` coordinates search, filtering, pagination and collocation state, while separate components render controls, tables, charts and result details. Normal searches and collocation concordances share request lifecycle handling, with distinct request parameters and response updates. Superseded concordance requests are aborted and their responses ignored.

## Data requirements

**The corpus XML and generated databases are not included in this repository.** You need your own authorised copy of the appropriate annotated Spoken BNC2014 XML, or a compatible database previously generated by this project. Obtain and use corpus material under the provider's applicable terms.

A fresh clone can build the frontend and run the synthetic API/frontend tests without the full corpus. Meaningful corpus searches require an ingested database.

## Local setup

### Requirements

- Node.js with support for running the project's TypeScript files directly. The local application has been run with Node 24.
- npm.
- Python 3 and SQLite with FTS5 support if rebuilding the corpus database.
- An existing compatible corpus database or the XML files needed to create one.

`better-sqlite3` is a native dependency. Installing it may require platform build tools if a suitable prebuilt binary is unavailable.

### Install dependencies

From a fresh clone:

```bash
git clone https://github.com/lw1066/spoken_bnc_concordancer.git
cd spoken_bnc_concordancer
npm ci
npm ci --prefix frontend
```

Backend dependencies and tests are managed by the root `package.json`; there is no separate `backend/package.json`.

### Supply the database

For an existing installation, keep `bnc_corpus.db` in the project root. Moving the whole project folder preserves this relative location.

To build a database from XML, put the corpus files in `corpus_files/` and run from the project root:

```bash
python3 scripts/ingest_bnc.py
```

**This script deletes and rebuilds an existing `bnc_corpus.db`.** Stop the API and back up any database you need before running it. Ingestion is a setup operation, not part of normal application startup, and can take time for a full corpus.

### Start the backend

From the project root:

```bash
node backend/server.ts
```

Or, if your terminal is already inside `backend/`:

```bash
node server.ts
```

The API listens on `127.0.0.1:8000`. Open [localhost:8000](http://localhost:8000/) to check its status. The database path is resolved relative to the project, rather than the terminal's working directory.

To select another database filename relative to the project root:

```bash
CORPUS_DB=bnc_corpus_test.db node backend/server.ts
```

### Start the frontend

In a second terminal, from the project root:

```bash
npm run dev --prefix frontend
```

Open the address printed by Vite, normally [localhost:5173](http://localhost:5173/). Keep both terminals running.

The frontend defaults to `http://localhost:8000` for API requests. To change this, create `frontend/.env.local`:

```dotenv
VITE_API_BASE_URL=http://localhost:8000
```

Restart Vite after changing environment variables. The API's CORS allowlist currently includes `http://localhost:5173` and the project's Netlify frontend origin. A different frontend origin requires a corresponding configuration change in `backend/app.ts`.

## Example workflow

1. Search for `honestly` as a word and inspect its concordance lines.
2. Search for `hard*`, then select one vocabulary variant to narrow the results.
3. Open collocations for the selected target and adjust the left/right windows.
4. Select a collocate or distribution position to inspect the matching examples.
5. Open a result to see its utterance and available metadata.

Broad word or lemma results need a single selected vocabulary variant before collocation analysis is available. Phrase searches have a separate collocation path.

## API overview

| Endpoint                            | Purpose                                                                      |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| `GET /`                             | API status                                                                   |
| `GET /api/search`                   | Word, lemma and phrase concordances, counts and vocabulary variants          |
| `GET /api/collocations`             | Collocate frequencies and relative-position counts                           |
| `GET /api/collocations/concordance` | Concordances for a target/collocate pair, optionally at a specified position |

Example word search:

```text
http://localhost:8000/api/search?query=honestly&search_type=word&window_size=5&limit=20&page=1
```

Lemma searches supply the `lemma` query parameter. Phrase searches use `query` with `search_type=phrase`. Collocation endpoints accept separate left/right windows; supported window sizes are 0–5.

## Checks

Run from the project root:

```bash
npm test
npm run test:backend
npm run test:frontend
npx tsc --noEmit -p backend/tsconfig.json
npm run lint --prefix frontend
npm run build --prefix frontend
```

Frontend validation currently passes lint, all 115 tests across 12 suites, and the production build. Vite reports an advisory bundle-size warning. The backend test suite also passes on the local Mac installation.

The combined `npm test` command runs backend tests followed by frontend tests. API tests construct an in-memory SQLite database with synthetic examples. Frontend tests cover components and search behaviour using mocked dependencies.

A Python ingestion test is also present:

```bash
python3 -m unittest discover -s scripts/tests
```

It references `scripts/tests/fixtures/SQ2W-tgd.xml`, which is not tracked in this repository. Supply an appropriate permitted fixture before running that test.

## Current limitations and next steps

- Corpus data must be supplied separately; a small distributable sample would make evaluation easier.
- The ingestion test's XML fixture is currently absent from version control.
- Full-corpus performance depends on database size and query breadth; benchmarks should identify the dataset and environment used.
- The API currently binds to the local loopback interface. Remote hosting requires a deliberate deployment configuration; a hosted frontend alone does not host the API or corpus database.
- Further useful work includes collocation API regression tests and a documented demonstration with screenshots.
